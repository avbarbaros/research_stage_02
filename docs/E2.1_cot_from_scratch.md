## 2. Setup

| Condition | System prompt | User turn | `max_new_tokens` |
|---|---|---|---|
| `direct` | "Output only the final numeric answer — a single number, nothing else." | question | 64 |
| `zero_shot_cot` | "Think step by step, then state the final answer as: 'The answer is \<number\>.'" | question + "Let's think step by step." (Kojima et al.) | 512 |
| `few_shot_cot` | "Solve each problem step by step and end with 'The answer is \<number\>.'" | 8 hand-written exemplars as chat turns, then the question | 512 |
| `few_shot_cot_wei` | same as `few_shot_cot` | the 8 standard GSM8K exemplars from Wei et al. (2022), then the question | 512 |

- Decoding is plain greedy: `do_sample=false`, `repetition_penalty=1.0` (this overrides the
  `1.05` that Qwen2.5's `generation_config.json` would otherwise add).
- All four conditions see the **same 300 questions**, and the two few-shot conditions share a
  system prompt, so the only difference between them is the exemplars.
- Accuracy comes with a **Wilson 95% confidence interval**.

## 3. Results

| Condition | Accuracy | 95% CI (Wilson) | Correct / 300 | Extraction failures | Mean response length (chars) | Wall time |
|---|---:|---:|---:|---:|---:|---:|
| `direct` | **21.3%** | [17.1, 26.3] | 64 | 0 | 2.3 | 1.1 min |
| `zero_shot_cot` | **90.3%** | [86.5, 93.2] | 271 | 0 | 837.6 | 77.1 min |
| `few_shot_cot_wei` | **90.0%** | [86.1, 92.9] | 270 | 0 | 518.2 | 51.2 min |
| `few_shot_cot` (hand-written) | **88.3%** | [84.2, 91.5] | 265 | 0 | 470.4 | 47.3 min |

Observed ordering:

```
zero_shot_cot (90.3) ≈ few_shot_cot_wei (90.0) ≈ few_shot_cot (88.3)  ≫  direct (21.3)
```

**Reference point.** The Qwen2.5 technical report lists about 91.6% on the full GSM8K test set
(1,319 questions) for Qwen2.5-7B-Instruct. Our CoT numbers on a 300-question subset
(88.3–90.3%) fall inside that range given the ±3.5 pp interval width, so the harness shows no
sign of a systematic scoring error.

## 4. Interpretation

### 4.1 The main effect: reasoning ≫ direct answering

Writing out intermediate steps raises accuracy from 21.3% to about 90%, a **4.2× improvement**.
The intervals are far apart ([17.1, 26.3] vs [86.5, 93.2]), so this effect is clear even at
n = 300. This matches the central claim of Wei et al. (2022) and Kojima et al. (2022): for
multi-step arithmetic word problems, a model of this size cannot do the computation "in one
token" and needs the generated steps as working memory.

The direct condition shows the failure in its purest form. On the first test question
(Jared's typing speed: the average of 47, 52 and 57), the direct answer is **50**. That is
close to the right answer of 52 but wrong: the model guessed the scale of the result without
doing the arithmetic. All four CoT conditions get 52.

### 4.2 The deviation: zero-shot CoT is not worse than few-shot CoT

Both original papers report **direct < zero-shot CoT < few-shot CoT**. We find zero-shot CoT
equal to or slightly above both few-shot variants (+0.3 pp over Wei exemplars, +2.0 pp over the
hand-written ones). The three CoT intervals overlap heavily, so **the three CoT variants are
statistically indistinguishable** at n = 300.

The likely reason is that the original papers used **base (non-instruction-tuned) models**
(PaLM, GPT-3). Qwen2.5-7B-Instruct was post-trained on large amounts of step-by-step math
solutions, so a plain instruction already triggers a full, well-structured reasoning chain.
For a base model, the exemplars teach the *format* of reasoning. For this model, the format is
already learned, and the exemplars mainly change the *style*:

- Few-shot responses are **38–44% shorter** (470–518 chars vs 838 chars). The exemplars are
  terse, and the model copies that brevity.
- The shorter style costs little accuracy (−0.3 to −2.0 pp, not significant) and saves
  **34–39% of generation time**.
- The hand-written exemplars score slightly below the Wei exemplars. Both sets have 8 items
  and the same system prompt, so exemplar content does matter a little, but the difference
  (1.7 pp) is well inside the noise.

**Conclusion for the thesis:** the "few-shot beats zero-shot" result does not carry over to
modern instruction-tuned models. Whatever a prompting method adds should be measured against
zero-shot CoT, not against direct prompting. This matters for Stage 3 (E3.1, E3.2), where the
same comparison is repeated with a VLM.

### 4.3 Cost

Zero-shot CoT produces the longest outputs (1.6–1.8× the few-shot length) for the same
accuracy. Direct prompting is about 70× cheaper but almost useless on this task. This is the
first data point for the compute–accuracy trade-off studied in E2.2.

## 5. Answer-extraction pitfalls

Extraction lives in `extract_pred()` in [`reasoning_utils.py`](../reasoning_utils.py). The
ground truth is the number after `####` in the GSM8K answer field (`extract_gt()`).

**Strategy:** search for a trigger phrase ("the answer is", "the final answer is",
"therefore, the answer is", "so the answer is", "####", "answer:"). If one matches, take the
number after it. Otherwise fall back to the **last number in the text**. Predictions are
compared numerically (`float(pred) == float(gt)`), so `"18"`, `"18.0"` and `"018"` count as
equal.

| # | Pitfall | Example | How it is handled |
|---|---|---|---|
| 1 | Thousands separators | `1,234` | Commas are stripped before `float()` |
| 2 | Units or currency next to the number | `42 apples`, `$17` | The number pattern does not need to sit at the end of the string |
| 3 | Several numbers in a CoT response | every intermediate result is a candidate | A trigger phrase wins; otherwise the last number is used, since CoT answers usually end with the result |
| 4 | Negative and decimal numbers | `-3`, `0.5` | The pattern allows a leading `-` and a decimal part |
| 5 | Sentence-final period glued to the number | `The answer is 52.` | **Bug found and fixed** (commit `3bfabd1`): the old pattern `-?[\d,]+\.?\d*` allowed a bare trailing `.`, so the period could be captured as part of the number. The new pattern `-?[\d,]+(?:\.\d+)?` only accepts a decimal point followed by digits |
| 6 | No number in the output | refusal, truncation | Returns `None`, which counts as wrong without crashing |
| 7 | Formatting the prompt did not ask for | `\boxed{52}`, `\[ \text{The answer is 52.} \]` | The trigger still matches inside LaTeX; `\boxed{}` with no trigger falls back to the last number, which is the boxed value |
| 8 | Format compliance in direct mode | the model might explain instead of answering | The direct prompt plus a 64-token cap gave a mean response of 2.3 characters, so compliance was effectively 100% |

**Result:** 0 extraction failures in all four conditions (1,200 responses). The low direct
score is therefore a reasoning failure, not a parsing failure.

**Known remaining risks** (did not occur here, but worth keeping in mind for later stages):

- The fallback treats a comma-separated list such as `3,4,5` as the single number `345`. This
  can only happen when no trigger phrase matches.
- With several triggers present, the match from the trigger that comes **later in the trigger
  list** wins, not necessarily the match that appears last in the text.
- A response cut off at `max_new_tokens` with no trigger falls back to an intermediate number.
  This matters more in E2.2, where 1.4% of samples were truncated.
- **Multi-part answers:** for "how many red and blue boxes are left?", some sampled answers say
  "The answer is 4 blue and 6 red", and the trigger captures 4 instead of the total, 10. This
  was seen in E2.2 samples (question 3, 7 of 32 samples); voting hides it when most samples
  state the total.
- **Base models keep generating after the answer** and invent new problems, so the last
  number, or a Kojima stage-2 answer, can belong to an invented problem
  ([E2.1-B §5](E2.1_base_model.md#5-prompt-design-notes)). Base-model runs therefore stop at
  several question formats and cross-check the answer stated in the reasoning.
- **Lone commas (fixed after these runs):** the old number pattern `-?[\d,]+…` also matched a
  bare `,`, so the last-number fallback could return an empty string, which was scored as
  wrong but not counted as an extraction failure (e.g. `\boxed{52}, done`). The pattern now
  has to start with a digit. The E2.1/E2.2 numbers above were produced before the fix; any
  effect would show as a few answers that change when the saved responses are re-extracted.

## 6. Limitations

- **n = 300** gives ±3.5 pp intervals. That is enough to separate CoT from direct, but not to
  rank the three CoT variants. Running all 1,319 questions would shrink the intervals to about
  ±1.7 pp.
- Each condition was run in a separate job, so the `comparisons` field (exact McNemar test
  against `zero_shot_cot`) is empty in these files. A paired test between the CoT variants
  needs a single run with all conditions, or a post-hoc merge of the per-question records.
- One model, one seed, greedy decoding. Whether the ordering depends on model scale (the
  "emergence" caveat in Wei et al.) is not tested here.

## 7. What this result feeds into

- **E2.2** uses the `zero_shot_cot` prompt and its greedy result (90.3%) as the baseline for
  self-consistency.
- **E3.1 / E3.2:** zero-shot CoT, not direct prompting, is the fair reference when asking
  whether multimodal CoT helps.
- The extraction module is reused unchanged in E2.2 and later experiments, so the pitfalls
  above apply to every downstream number.

## 8. Base-model run (Qwen2.5-7B)

The explanation in §4.2, that instruction tuning removes the benefit of few-shot exemplars,
was tested on the base model in **[E2.1-B](E2.1_base_model.md)** (100 questions).

| Condition | Base | Instruct (this page) |
|---|---:|---:|
| direct | 28.0% | 21.3% |
| zero-shot CoT | 82.0% | 90.3% |
| few-shot CoT (Wei) | 85.0% | 90.0% |
| few-shot CoT (hand-written) | 79.0% | 88.3% |

The base model shows the **same ordering**: CoT ≫ direct, and the three CoT variants within
±3 pp of each other (McNemar p = 0.61). So the explanation is **not supported for Qwen2.5**.
The more likely reading is that Qwen2.5's pretraining data already contains instruction-style
GSM8K material, so even the "base" model knows the answer format and gains little from
exemplars. A base model with less such data (Mistral-7B-v0.1, Llama-2-7B) is needed to test the
original explanation properly. Instruction tuning itself adds roughly 5–9 pp to every CoT
condition.
