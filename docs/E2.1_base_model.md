| | |
|---|---|
| **Stage** | 2 — Reasoning Methods in Language Models (ablation of [E2.1](E2.1_cot_from_scratch.md)) |
| **Model** | `Qwen/Qwen2.5-7B` (base, no instruction tuning; bfloat16, greedy decoding) |
| **Dataset** | GSM8K test split, first 5 of the E2.1 questions (seed 42) |
| **Command** | `python e2_1_cot_from_scratch.py --model base --n_eval 5` |
| **Result file** | `outputs/e2_1_results_20261101_1437_base.json` |
| **Status** | ⚠️ Run B1 complete. Few-shot conditions valid; `direct` and `zero_shot_cot` mis-scored by two prompt bugs (§3). Both bugs fixed in code (§5); 300-question run pending |

---

## 1. Why this run

E2.1 on Qwen2.5-7B-**Instruct** found zero-shot CoT ≈ few-shot CoT, while the original papers
(which used base models) report few-shot > zero-shot. The hypothesis is that **instruction
tuning removes the benefit of exemplars**. If it is right, the same model *without*
instruction tuning should show the papers' ordering:

```
direct  <  zero-shot CoT  <  few-shot CoT
```

## 2. Setup

The base model has no chat template, so prompts follow the original papers' plain-text format
(`e2_1.base_prompts` in [config.yaml](../config.yaml)):

| Condition | Prompt | Answer taken from |
|---|---|---|
| `direct` | `Q: {q}\nA: The answer (arabic numerals) is` | first number in the completion |
| `zero_shot_cot` | Stage 1: `Q: {q}\nA: Let's think step by step.` → Stage 2: stage 1 + reasoning + `\nTherefore, the answer (arabic numerals) is` (Kojima et al.) | first number after the stage-2 trigger |
| `few_shot_cot` / `few_shot_cot_wei` | the E2.1 exemplar files as `Q: …\nA: …` blocks, then `Q: {q}\nA:` | trigger phrase / last number |

There is no system prompt, and generation stops at `\nQ:`. All four conditions ran in one job,
so the results file includes paired McNemar tests.

## 3. Results

| Condition | Correct / 5 | Accuracy | Wilson 95% CI | Extraction failures | Mean response (chars) | Time |
|---|---:|---:|---:|---:|---:|---:|
| `direct` | 0 | 0% | [0, 43.5] | 2 | 166 | 18 s |
| `zero_shot_cot` | 1 | 20% | [3.6, 62.5] | 0 | 1,245 | 124 s |
| `few_shot_cot` | 4 | 80% | [37.6, 96.4] | 0 | 233 | 31 s |
| `few_shot_cot_wei` | 5 | 100% | [56.6, 100] | 0 | 295 | 36 s |

Paired against `zero_shot_cot` (exact McNemar): few-shot +60 pp (p = 0.25), Wei few-shot +80 pp
(p = 0.125), direct −20 pp (p = 1.0). None is significant at n = 5.

**These numbers cannot be read as they stand.** The responses show that two of the four
conditions are scored wrongly.

### 3.1 Bug A — zero-shot CoT: the wrong answer is extracted

The base model solves the problem and writes "The answer is 52." Then, being a base model, it
**keeps writing the document**: it invents new problems in formats the `\nQ:` stop string does
not catch (`Question:` / `Answer:`, `[Question]` / `[Answer]`). The Kojima trigger is appended
after this invented text, so the model completes it with the answer to the *last invented
problem*:

| Q | Model's own answer to the real question | Invented problems after it | Extracted | GT |
|---|---|---:|---:|---:|
| 0 | "The answer is 52." ✓ | 2 | 1000 | 52 |
| 1 | "The answer is 5." ✓ | 2 | 40 | 5 |
| 2 | "The answer is: 83." ✓ | 0 | 83 | 83 |
| 3 | "The answer is 10." ✓ | 2 | 1000 | 10 |
| 4 | "The answer is 40." ✗ | 2 (cut at 512 tokens) | 146 | 70 |

Scored on the model's own first answer, **zero-shot CoT gets 4/5, not 1/5.** The invented
text also inflates the response length (1,245 chars) and run time (~25 s per question vs ~6 s
for few-shot).

This is answer-extraction pitfall #3 (several number candidates) in a form specific to base
models. An instruction-tuned model ends its turn with an end-of-sequence token; a base model
does not.

### 3.2 Bug B — direct: the model does not give a number

After "The answer (arabic numerals) is", the model writes `: `, nothing, or starts explaining
("Explain how we arrive at this answer: …", "A: To find … 1. Identify …"). The 64-token limit
cuts the explanation off before any result appears. First-number extraction then picks up list
numbering (`1.`) on 3 questions and finds nothing on 2. **0/5 says nothing about the model's
direct-answering ability.**

### 3.3 The few-shot conditions are valid

Responses copy the exemplar format, end with "The answer is N.", and stop cleanly at the next
`Q:`. The one few-shot error (Q4, hand-written exemplars, 40 instead of 70) is a real reasoning
error: "half as many helmets as footballs" is read the wrong way round. The base model makes
the same mistake under zero-shot CoT, and the Instruct model makes it in some E2.2 samples.

## 4. Interpretation so far

After re-scoring Bug A by hand: **zero-shot CoT 4/5, hand-written few-shot 4/5, Wei few-shot
5/5.** On these 5 questions there is no sign of the large few-shot advantage the hypothesis
predicts, but n = 5 cannot show a difference of the expected size.

One observation already matters for the full run. The invented problems use GSM8K-style
`[Question]/[Answer]` templates, so Qwen2.5 "base" has evidently seen a lot of
instruction-style math data during pretraining. Even a clean 300-question run may therefore
show only a small zero-/few-shot gap, for one of two reasons:

1. instruction tuning is not what removes the few-shot benefit, or
2. Qwen2.5 "base" is already close to an instruction-tuned model, so it does not test the
   hypothesis well.

To tell these apart, run a base model with less instruction-style pretraining data (for
example `Mistral-7B-v0.1` or `Llama-2-7b-hf`).

## 5. Fixes before the 300-question run

All three changes below are implemented ([config.yaml](../config.yaml) `e2_1.base_prompts`,
[e2_1_cot_from_scratch.py](../e2_1_cot_from_scratch.py)). The direct prompt is therefore no
longer Kojima's "The answer (arabic numerals) is", which run B1 used. The new results file
reports `stage2_vs_stage1_mismatches` and `accuracy_stage1` for zero-shot CoT.

A related fix in the shared extraction code: the number pattern no longer matches a lone comma
([E2.1 §5](E2.1_cot_from_scratch.md#5-answer-extraction-pitfalls)). This affects every
experiment that re-extracts answers.

| Bug | Fix | Effect |
|---|---|---|
| A | Extend `e2_1.base_prompts.stop_strings` to `["\nQ:", "\nQuestion:", "\n[Question]"]` | Stage 1 ends at the first invented problem, so the stage-2 trigger follows the model's own reasoning |
| A (check) | Also store the trigger-phrase answer from stage 1 (`extract_pred(reasoning)`) and count disagreements with the stage-2 answer | Any remaining extraction leak shows up in the results file |
| B | Make base `direct` use Wei et al.'s **standard prompting**: the same 8 exemplars with the reasoning removed (`A: The answer is 6.`) | This is the direct baseline Wei et al. used for base models. Exemplars, not instructions, set the format for a base model |

Expected cost of the full run after the fixes is about 1.5–2 h (four conditions, 300
questions), down from about 3 h, because zero-shot CoT will no longer generate up to 512 tokens
of invented text.

## 6. Limitations

- n = 5: only qualitative findings (the two bugs) are reliable. The accuracies are not.
- The hand re-scoring in §4 uses the trigger-phrase answer from the stage-1 reasoning. That
  is a different rule from the Kojima protocol used for the reported numbers, so the 4/5
  figures are not directly comparable to the table in §3.
